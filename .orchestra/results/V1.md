### C. Database (read-only sqlite3)
- `.schema bookmarkHistory` is the same as `packages/db/drizzle/0098_bookmark_history.sql`. The columns are id TEXT PK, and bookmarkId, userId, changeId and field (TEXT NOT NULL). oldValue and newValue are nullable TEXT, and createdAt is INTEGER NOT NULL. Both FKs have ON DELETE CASCADE: bookmarkId points to bookmarks.id, and userId points to `user`.id (the SQL name of the users table). There is an index `bookmarkHistory_bookmarkId_createdAt_idx` on (bookmarkId, createdAt).
- `__drizzle_migrations` has 99 rows. The newest row has hash `5514a553…cc29` (equal to `shasum -a 256` of the 0098 SQL file) and created_at `1795546646024` (equal to the journal entry `0098_bookmark_history` `when`).
- `git status` under packages/db/drizzle shows `M meta/_journal.json`, `?? 0098_bookmark_history.sql` and `?? meta/0098_snapshot.json`, and nothing else.
- `createdAt` values are stored in milliseconds, for example `1795547084555`.

### D. End-to-end over HTTP (dev server at :3000)
User A id `zgxecub3o2x0iasrp2i9btz0`. Link bookmark `mfcmr022fbfsn3zctdw9i0hh` was created with title "Original". Text bookmark `s3yj7zr969efwr9bm0qnh3hf` was created with text "hello".
1. `getBookmarkHistory` right after creation: `{"result":{"data":{"json":{"history":[]}}}}` HTTP 200.
2. PATCH `{"title":"Edited"}` gives one row `{"field":"title","oldValue":"Original","newValue":"Edited","userId":"zgxecub3o2x0iasrp2i9btz0","changeId":"200d7231-…","createdAt":"2026-11-24T19:04:40.328Z"}`.
3. PATCH `{"title":"Edited"}` again: still that single row.
4. PATCH `{"title":"Edited twice","description":"A new description"}` gives the order [description null→"A new description", title "Edited"→"Edited twice", title "Original"→"Edited"]. The first two share changeId `710d0438-…` and createdAt `…44.555Z`, and both come before the older row.
5. PATCH `{"note":"my private note"}` puts a `note` row (null→"my private note") at the top for the owner.
6. PATCH `{"archived":true}` (HTTP 200): still 4 rows `['note','description','title','title']`.
7. Text bookmark: PATCH `{"text":"hello world"}` gives a `text` row hello→hello world. PATCH `{"url":"https://example.com/should-fail"}` gives `Attempting to set link attributes for non-link type bookmark` HTTP 400, and the history still has 1 row. Extra check: PATCH `{"text":"should be rolled back","url":…}` gives HTTP 400, the history still has 1 row, and the stored text is still "hello world" (the transaction rolled back).
8. User B reading A's link and text bookmark histories gets `{"message":"Bookmark not found","code":-32004,"data":{"code":"NOT_FOUND","httpStatus":404,…,"path":"bookmarks.getBookmarkHistory"}}`. For comparison, B's REST GET of the bookmark gives 404, and B's PATCH of A's title gives 404 `Bookmark not found` (extra check).
9. With no Authorization header: `{"message":"UNAUTHORIZED","code":-32001,"data":{"code":"UNAUTHORIZED","httpStatus":401,…}}`.
10. Before the delete, sqlite had exactly 5 rows for these 2 bookmark ids, with the same ids, changeIds, fields, values and ms timestamps as the HTTP responses. The empty old values are real SQL NULL (`typeof` = null). DELETE of both bookmarks returned HTTP 204. Afterwards sqlite shows `history rows for ids: 0`, `bookmarks rows for ids: 0`, and `total history rows: 0`. After the delete, getBookmarkHistory returns NOT_FOUND to the owner.
