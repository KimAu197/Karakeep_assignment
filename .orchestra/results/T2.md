# T2 result: History section in the bookmark detail sidebar

## What was done
- New `HistoryBox` component (modelled on `HighlightsBox`): loads `bookmarks.getBookmarkHistory` with `useTRPC` + `useQuery`, groups rows by `changeId` (a `Map` in first-seen order, so the server's newest-first order is kept), and renders one entry per save:
  - entry header: relative time from the existing `useRelativeTime` hook, in a `<time dateTime=ISO title="PP, p local time">` element;
  - per changed field: i18n field label, old value (muted), then an arrow and the new value; screen-reader-only "Before:" / "After:" labels;
  - values rendered as plain React text (no HTML, no markdown), `line-clamp-3 whitespace-pre-wrap break-words`, so long notes or URLs cannot widen or blow up the sidebar;
  - `null` or `""` shown as a muted italic "empty" label.
  - States: loading (spinner + "Loading history…"), error ("Couldn't load the history"), empty ("No changes yet").
  - Uses the existing shadcn `Collapsible` with the same trigger styling as `HighlightsBox`; the trigger shows "History" plus the number of saves once loaded. **Collapsed by default** (see decisions below).
- Mounted in `BookmarkPreview.tsx` at the end of `detailsSection`, after `AttachmentBox`, preceded by a `<Separator />`. Mounted for everyone who can see the sidebar; no privacy logic in the UI (server filters `note` rows for non-owners).
- `useUpdateBookmark.onSuccess` now also calls `queryClient.invalidateQueries(api.bookmarks.getBookmarkHistory.queryFilter({ bookmarkId: req.bookmarkId }))`, in the same style as the existing `getBookmark` invalidation. Purely additive; other callers (web, mobile, browser extension) are unaffected apart from one more cache invalidation. Note autosave (`useNoteDraft`) also goes through this hook, so note edits refresh the history too.
